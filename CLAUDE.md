# BiteDown: agent rules

iOS app that tracks fridge and pantry food, predicts expiry, flags spoilage from photos, suggests
recipes from expiring items, and lets friends and groups share surplus. Removing food with an
outcome is how waste is measured. Product: [`docs/IDEA.md`](docs/IDEA.md). Status:
[`HANDOFF.md`](HANDOFF.md). Screens: [`docs/design/SCREENS.md`](docs/design/SCREENS.md).

## Rules
- Secrets live in `.env` only (and as Colab secrets for training). Never hardcode, commit or print
  them. Keep `.env.example` current with placeholders.
- Run Python from the project venv (`.venv`, `.venv-ml`), never the global interpreter. Pin every
  dependency.
- Any change to architecture, endpoints, schema, setup or the ML data contract updates `docs/` in
  the same PR.
- Update `HANDOFF.md` and the affected `docs/` at every checkpoint (a PR merged, a QA verdict, a ruling,
  a milestone) and at the end of every work session. Status, the in-flight table, next steps and QA status
  must match what's merged, so a fresh session can pick up from `HANDOFF.md` alone.
- Feature branches and PRs into `main` only. Never push to `main`. Small commits with clear
  messages.
- Verify before claiming done: run the code, hit the endpoint, build the app. A builder's own
  check doesn't count; a QA sign-off does.
- Before pulling images, models or datasets, check free disk space. Delete only what you created.
- Never kill processes by pattern. Record the PID of anything you start and kill only that.

| Layer | Choice |

## Process
- The orchestrator plans, rules on disputes, reviews and **merges**. Builder sessions open PRs and
  never merge. Sub-agents never run git.
- Every builder is paired with a QA agent that starts at the same time, in the same worktree, and
  writes only in its own paths. **QA never edits feature code.**
- Never let two agents edit the same file. Anything outside your paths is a request to its owner.
- One heavy run at a time: Docker builds, full test suites, training. On the Mac the shared lock is
  `<scratchpad>/heavy.lock` (`mkdir` it, write your name to `owner`):
  - Never run a heavy job without holding the lock, even after a wait timeout. Report and stop instead.
  - Remove the lock only when `owner` is your own name.
  - Hold it for one invocation, then release it, so parallel agents interleave. Iterate on targeted tests and run the
    full suite once, at the end.
- **Deadline mode ended (owner, 2026-10-19):** the heavy lock is back, and PRs wait for green CI again (short PR CI:
  `docs/DECISIONS.md` 2026-10-19). Each agent still uses its own simulator and DerivedData. Codex may take tasks under
  the same rules as sub-agents (own worktree, no secrets, no live Gemini, no force-push, never merge).
- Backend tests use `TEST_DATABASE_URL` only. The suite rebuilds that schema under an advisory
  lock. Never touch it from outside the suite.
- Agents report against the API contract in `docs/API.md`. When code and contract disagree, the
  orchestrator rules and the contract is updated in the same PR.
- Work ported from someone else carries `Co-authored-by: <their GitHub noreply email>` on every
  ported commit.
- Never delete a branch that an open PR targets.
- Never quote a PR number before `gh pr create` returns it, because other sessions open PRs in the gap.
- Merge with merge commits. Before merging, rebase onto `main` (on a teammate's branch, merge `main` in instead: never rewrite or force-push someone else's branch) and confirm CI actually ran and passed. A workflow skipped by its path filters is acceptable only for docs- or script-only PRs.
- The orchestrator records every ruling (contract, data or design) in `docs/QA.md` or `docs/DECISIONS.md` in the PR that applies it.
- QA bug IDs are global per area (`BE-n`, `ML-n`, `IOS-n`, `PL-n`): before numbering, check the highest ID in
  `docs/QA.md` **and** in open PRs' `docs/qa/*.md`, because parallel branches have collided. When several QA agents
  run at once, give each its own ID block up front (e.g. IOS-30…39) and record the blocks in `HANDOFF.md`.
- Big data, venvs and model runs live outside git (`../mldata/`), never in the repo or a worktree.

## Data rules
- A new dataset is used only after its licence is verified and its attribution is written in `docs/ML.md`,
  `docs/PIPELINE.md` and `README.md`. Anything unverified stays `"pending": true` in `sources.json`.
- Add a source as an adapter in `pipeline/ingestion/` plus a `sources.json` entry, and mirror it in the Colab notebook.
- Verify every download (SHA-256, MD5 or the archive's own CRC). Fetch only what is used: never pull a whole archive when a
  subset will do (MeatScan is range-read from its 25 GB RAR).
- Exclude a release's own augmented copies, cap each class x freshness cell, and group so the same specimen, batch or
  capture session never straddles train / val / held-out. Labels the release doesn't give (e.g. freshness from storage
  days) are a data-owner ruling, recorded in `docs/PIPELINE.md`.
- Roboflow downloads need the **private** API key; the `rf_`-prefixed publishable key is rejected.
- Long-running agents wait for each other's heavy runs (xcodebuild vs the backend suite) instead of
  running them in parallel. Give the waiting agent a time limit; its fallback is to report and stop, never to run
  without the lock.

## Merge gate
- A PR merges only with a QA pass recorded in `docs/qa/<area>.md`, then folded into
  [`docs/QA.md`](docs/QA.md), plus green CI.
- A QA failure goes back to the builder. It's never merged around.
- Anything that breaks the demo path is a blocker: photo add → expiry prediction → remove → Impact.
- Thresholds and data rules live in `docs/QA.md`, including the leakage, stratification and binary
  freshness gates. Metrics from a split that fails them are invalid and must not be quoted.
- Parser changes are measured on a **blind** holdout the builder has never seen. A holdout used
  for fixing is no longer blind.

## Core domain rules
- Removal is a soft delete: `outcome ∈ {used, donated, thrown_out}`. `waste_reason` is required
  if and only if the outcome is `thrown_out`.
- Every removal writes exactly one `remove` event in the same transaction. A `donated` removal
  fulfils an open share listing. Undo (`/restore`) must leave impact exactly as it was before.
- Impact is computed from `food_events`, never stored as totals.
- Freshness is `fresh | semi_fresh | spoiled`. `semi_fresh` shows as "Use soon". YOLO gates are
  spoiled vs not-spoiled.
- Visibility: friend-scoped items are visible to accepted friends only, group-scoped items to
  current members only. A listing or request the caller can't see returns 404.

## Design and UI
- The design canvas (https://claude.ai/artifact/ALmB8FYKGrayhDQXqvoncx) and `docs/design/` are
  the source of truth. iOS builds only approved screens. Only the orchestrator publishes to the
  canvas. Read an artboard from the canvas before editing it, publish only the files you changed,
  and mirror every canvas change into `docs/design/screens/` in the same PR.
- Translate designs into native SwiftUI. Every colour, size and font comes from
  `ios/App/Theme.swift`, which mirrors `DESIGN_SYSTEM.md`. No ad-hoc values in views.
- Use native components where the design system says so: the glass `TabView` (Add is a tab that
  presents a sheet), sheets, swipe actions, `ContentUnavailableView`, data scanner, document
  camera, and the official Google button.
- Every data screen has empty, loading (skeleton) and error states.
- Motion follows [`docs/design/MOTION.md`](docs/design/MOTION.md), using the `Theme.Motion` tokens:
  - Never delay an action for an animation. The tap takes effect immediately.
  - Never animate on every data refresh. Staggers run on first load or a new result only.
  - The whole sequence, stagger delays included, finishes within 0.5 s.
  - A composite (for example a stacked bar) animates as one unit. Labels appear after the shape they describe.
  - No decorative motion: no confetti, bouncing, parallax or idle loops. Only loading and listening may loop.
  - Pair haptics with key moments only: add, remove, claim, success and error.
  - **Respect Reduce Motion.** Movement, scaling, shakes and shimmer become fades. Counters show their final value. Haptics and colour or state changes stay.
- Accessibility is required: VoiceOver labels, Dynamic Type to AX5, 44 pt targets, AA contrast,
  Reduce Motion, and colour never the only cue.
- An iOS PR that deviates from an artboard includes a **Design delta** section with a Simulator
  screenshot. The orchestrator updates the canvas on merge.
- Never run Impeccable while generating UI. UI review (Impeccable critique and polish, then
  web-design-guidelines) runs once, when the UI is feature-complete.

## Conventions
- API: JSON, `snake_case`, ISO-8601 UTC, JWT bearer, errors as
  `{"error": {"code", "message"}}` with the right status code.
- Python: blueprints in `routes/`, logic in `services/`, and one service module per external
  dependency, so tests can stub it.
- Swift: one view per file. `APIClient` protocol with Live and Mock clients. Stable
  `accessibilityIdentifier`s (`screen.element.id`).
- Tests: `backend/tests/test_<area>.py`, `ios/Tests/{UnitTests,UITests}`, `ml/eval/tests`,
  `pipeline/tests`.
- **iOS test plans** (`ios/TestPlans/`):
  - **Smoke** gates every PR: all unit tests plus the UI smoke set, including `DemoPathUITests`, the merge-gate demo path. A UI test for a demo-path step belongs in Smoke.
  - **Full** runs on `main`, nightly and on manual dispatch.
  - Run them with `xcodebuild … -testPlan Smoke|Full`.
- **Backend tests:**
  - Run in parallel with `pytest -n auto` (pytest-xdist; each worker uses its own `fwr_test_gw<N>` database).
  - Tag a test `@pytest.mark.slow` only if it really is slow (real servers, scaling checks). PR CI skips those, and `main` and nightly run everything.
